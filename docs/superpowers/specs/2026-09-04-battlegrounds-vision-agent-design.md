# 酒馆战棋视觉规则自动化工具设计规格

日期：2026-09-04

## 1. 产品目标

开发一款 Windows 本地桌面工具，通过屏幕视觉识别《炉石传说》酒馆战棋购物阶段的可见信息，并依据用户预先配置的规则执行刷新、购买、上场、发现选择和卖出。

工具不读取游戏内存、不注入游戏进程、不绕过反作弊机制。运行与决策完全离线；网络仅用于用户主动触发的卡牌数据库更新。自动化仍可能违反游戏服务条款，产品必须在首次使用时明确提示账号风险。

## 2. 首版范围

### 2.1 支持范围

- Windows 10/11、简体中文游戏客户端。
- 16:9 画面比例，首批验证 1280×720、1600×900、1920×1080、2560×1440。
- 自动定位炉石窗口、购物阶段、商店、手牌、场面、金币、酒馆等级、刷新按钮和发现界面。
- 从公开卡牌库同步并缓存基础数据，同时允许用户手动导入截图补充或纠正。
- 用户可勾选多个目标随从；每张牌支持“不限购买”或指定购买数量。
- 未发现目标时自动刷新，但不得低于用户配置的金币保留下限。
- 每张牌可配置保留、买后上场并卖出、三连后上场并卖出、发现优先级和场上保护。
- 三连奖励和其他通用发现界面按人工优先级选择；均未命中时随机选择，避免阻塞。
- 发现获得的牌继续应用同一套规则。
- 默认保留两个手牌空位。
- 快捷键可作为动作执行后端；未配置快捷键的动作使用鼠标。
- F7 暂停或继续，F8 紧急停止，并立即禁止新的键鼠输出。
- 提供观察模式，只展示识别结果和拟执行动作，不发送键鼠输入。

### 2.2 首版不包含

- 不根据阵容、种族、战吼或实时战力进行 AI 价值判断。
- 不保证 16:10、4:3、超宽屏、移动端或非简体中文客户端。
- 不自动理解所有新卡或赛季机制的自然语言语义。
- 不读取日志、网络协议、游戏进程或内存作为决策输入。
- 不提供规避检测、隐藏进程或绕过反作弊的能力。

## 3. 设计原则

1. 安全优先：低置信度、未知界面或状态冲突一律停止，不猜测。
2. 单步闭环：每次只执行一个动作，验证状态变化后再计划下一步。
3. 身份与坐标分离：随从身份不绑定持久坐标，画面变化后旧坐标全部失效。
4. 快慢路径分离：普通刷新和购买走局部快速识别；三连、发现和卖出走严格复核。
5. 人工规则优先：首版所有保留、发现和卖出行为均由用户配置决定。
6. 模块隔离：视觉、状态、规则和输入模块通过明确数据结构通信，可单独测试和替换。

## 4. 系统架构

核心数据流如下：

`屏幕采集 → 视觉识别 → 状态快照 → 规则状态机 → 动作计划 → 输入执行 → 动作后复核`

### 4.1 桌面壳与界面

提供主配置窗口、游戏上方状态悬浮条和高风险动作确认弹窗。

- 主窗口使用“目标牌列表 + 单牌规则详情”布局。
- 状态悬浮条展示运行、暂停、识别中、等待动画、需要确认和错误状态。
- 高风险确认弹窗展示当前场面、拟卖随从缩略图、原因以及“确认卖出”“保持不动”。
- 关闭主窗口不得绕过紧急停止逻辑。

### 4.2 屏幕采集器

- 只截取炉石窗口与所需局部区域。
- 普通阶段以每秒 2–5 帧工作，战斗阶段停止高频识别。
- 使用连续帧差异判断动画是否稳定，避免固定长时间等待。
- 窗口尺寸、位置或 DPI 变化时触发重新校准。

### 4.3 布局定位器

- 通过稳定的界面锚点定位游戏区域。
- 将实际窗口映射为标准化 16:9 坐标系。
- 根据当前酒馆等级和商店槽位数量切分候选区域。
- 锚点不足或几何关系异常时输出“未知布局”，禁止操作。

### 4.4 卡牌识别器

- 对官方卡图和手动补图预计算感知哈希与局部视觉特征。
- 先以哈希快速召回候选，再以局部特征进行复核。
- 普通牌与金色牌分别保存模板，但共享同一基础卡牌标识。
- 输出卡牌标识、画面区域、候选分数和最终置信度。
- 置信度不足时返回 unknown，不返回最接近的卡牌作为确定结果。

### 4.5 数字与界面状态识别器

- 金币和酒馆等级优先使用轻量数字模板，不启用重量级通用 OCR。
- 发现、战斗、购物、未知弹窗等状态使用锚点和模板联合判断。
- 需要时允许为少数难识别元素加入轻量 ONNX 模型，但首版不依赖独立显卡。

### 4.6 状态跟踪器

每次稳定画面生成不可变的 `GameSnapshot`，至少包含：

- 窗口与布局版本；
- 当前阶段和置信度；
- 金币、酒馆等级；
- 商店、手牌、场面和发现候选；
- 是否手满、场满、存在三连或奖励；
- 截图时间和各识别项置信度。

任何会导致卡牌移动的动作都会递增布局版本。动作计划只能使用生成它的布局版本；版本不一致时必须废弃并重新规划。

### 4.7 规则引擎

每张目标牌使用统一规则模型：

- `purchaseLimit`：无限或指定数量；
- `normalAction`：保留或上场后卖出；
- `tripleAction`：保留或上场、处理奖励后卖出；
- `discoverPriority`：正整数，数值越小优先级越高；
- `protectedOnBoard`：是否禁止作为临时腾位出售目标；
- `executionOverride`：某动作的快捷键或鼠标执行方式。

发现得到的牌与商店购买的牌共享规则，不维护第二套行为定义。未配置牌只在发现兜底时允许被选择，其默认动作是保留；如无安全手牌空间则暂停，禁止擅自出售。

### 4.8 输入执行器

输入执行器支持两种后端：

- 快捷键：用户为具体动作配置单键或组合键后，程序模拟该按键。
- 鼠标：没有可用快捷键时，根据本次快照的新坐标执行点击或拖动。

动作执行前确认炉石窗口处于前台且布局版本一致。卖出动作不允许基于旧位置自动重试。执行后必须由视觉层确认预期变化，输入成功本身不代表业务动作成功。

## 5. 状态机与优先级

状态机每轮只选择一个动作，优先级从高到低为：

1. 紧急停止、非购物阶段、失去焦点或未知界面：禁止输入。
2. 阻塞弹窗与发现：按配置优先级选择，未命中时随机兜底。
3. 三连与奖励：金色牌上场，获取并使用奖励，处理发现，再应用卖出规则。
4. 手牌与场面空间：保证两个手牌空位；无法安全清理时暂停。
5. 购买目标：检查目标数量、金币和后续处理空间后购买。
6. 刷新酒馆：没有可购买目标且刷新后金币不低于保留下限时执行。

三连和发现可以产生新的三连、奖励或发现，因此每次处理后都回到优先级顶部重新评估，而不是继续执行旧队列。

## 6. 场满、手满与卖出安全

- 用户在配置阶段标记核心随从，核心随从默认受保护。
- 规则明确要求“上场后卖出”或“三连后卖出”的牌可以自动出售。
- 为三连临时腾场地需要出售其他随从时，必须暂停并询问用户。
- 确认弹窗显示拟出售对象；超时或无响应默认保持不动。
- 默认保留两个手牌位置。达到安全上限后停止购买和刷新，优先处理已配置的可出售牌、三连和奖励。
- 没有可安全处理对象时暂停，不处理保护牌。

卖出或上场会使其他随从移动。处理流程固定为：执行单一动作、等待画面稳定、鼠标移出识别区域、重新截图、重建所有位置、再生成下一动作。任何旧坐标不得跨越一次场面变化继续使用。

## 7. 快捷键与紧急停止

- 用户可为刷新、冻结、升级、购买、出售等动作配置快捷键。
- 配置快捷键后由程序自动发送，无需用户手动按键。
- 没有配置或测试失败的动作使用鼠标后端。
- 设置页提供单项快捷键测试，只有视觉确认动作成功后才标记为可用。
- F7 是程序级暂停/继续热键。
- F8 是程序级紧急停止热键，其监听优先于规则线程和输入队列。
- 紧急停止会清空待执行动作、释放可能按住的按键或鼠标按钮，并保持停止状态直到用户在主窗口重新启动。

第三方或所谓官方插件的快捷键不作为固定依赖。用户可以根据插件实际设置映射动作；无法验证的快捷键不能默认启用。

## 8. 性能预算

最低目标环境：Windows 10/11、四核 CPU、8 GB 内存、集成显卡。

- 稳定画面出现后 500 ms 内完成一次决策。
- 普通动作间隔目标为 400–800 ms，具体受游戏动画影响。
- 卡牌数据库特征在更新后一次性计算并缓存。
- 识别优先在感兴趣区域运行，不对全屏持续执行通用模型。
- 非购物阶段降低采集频率并禁止操作。

## 9. 异常处理

- 动作后未出现预期变化时，等待稳定画面并重新识别。
- 普通低风险动作最多自动恢复两次；之后暂停并展示失败前后截图与日志。
- 卖出属于高风险动作，不盲目重复拖动；必须重新定位和确认目标。
- 快捷键失败可按配置回退鼠标，但卖出不自动回退，必须暂停确认。
- 炉石窗口失去焦点、窗口几何变化、未知弹窗、识别冲突或截图失败时暂停。
- 日志记录截图引用、状态快照、规则命中、动作计划、执行结果和暂停原因，不记录账号凭据。

## 10. 卡牌数据更新

- 首次安装携带可用的缓存卡库，运行时无需联网。
- 用户主动更新时从公开卡牌来源同步元数据与图片，并生成本地特征缓存。
- 更新在独立暂存区校验完整性，通过后原子替换当前卡库。
- 更新失败保留旧版本，不影响离线运行。
- 用户补图覆盖自动模板，但必须绑定到明确卡牌标识并可随时撤销。

## 11. 测试与验收

### 11.1 单元测试

- 坐标归一化和 16:9 缩放。
- 卡图候选召回、置信度阈值和 unknown 分支。
- 金币、等级和界面状态识别。
- 规则优先级、购买数量、金币下限和发现随机兜底。
- 布局版本失效、F7、F8 和动作队列清空。

### 11.2 回放测试

- 使用脱敏录屏覆盖刷新、购买、手满、场满、三连、奖励、连续发现和随从移动。
- 回放模式只产生动作计划，不发送真实输入。
- 每次卡库或识别器更新都运行固定回放集，检查误识别和行为回归。

### 11.3 观察模式验收

- 在四种目标 16:9 分辨率上正确绘制识别框和拟执行动作。
- 低置信度目标显示 unknown 且不生成动作。
- 发现选择、金币下限和保护名单的命中原因可在界面查看。

### 11.4 端到端验收

- 完成“刷新 → 购买 → 三连 → 上场 → 奖励发现 → 新牌规则 → 卖出”闭环。
- 卖出导致随从移动后不得使用旧坐标。
- 场满临时卖怪必须等待确认，超时保持不动。
- F8 在任意状态下停止后续键鼠输出。
- 普通办公配置下满足 500 ms 稳定画面决策目标。

## 12. 分阶段交付

1. 视觉基础与观察模式：窗口定位、商店识别、卡库、规则编辑和覆盖层。
2. 安全购买循环：金币识别、刷新、购买、数量和金币下限。
3. 手牌与场面：上场、卖出、保护名单、空间管理和位置重建。
4. 三连与发现：奖励处理、发现优先级、随机兜底和递归事件。
5. 快捷键与稳健性：输入后端、F7/F8、回放集、性能与异常恢复。

每一阶段都先在观察或回放模式通过验收，再启用真实输入。
